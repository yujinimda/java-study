## 문제 1 — 증감연산자

```
5    ← i++    5를 쓴 뒤 6으로 올린다 (i=6)
6    ← i
7    ← ++i    7로 올린 뒤 7을 쓴다 (i=7)
7    ← i
16   ← i++ + ++i
9    ← i
```

마지막 줄을 추적하면 (시작 `i = 7`):

| 순서 | 식 | 이 식이 내놓는 값 | 계산 후 i |
|---|---|---|---|
| 1 | `i++` | **7** (쓰고 나서 올림) | 8 |
| 2 | `++i` | **9** (올리고 나서 씀) | 9 |
| 3 | `7 + 9` | **16** | 9 |

**외우는 법:** `++` 가 **앞에 있으면 먼저 올리고**, **뒤에 있으면 나중에 올립니다.**
`++` 의 위치가 곧 "언제 올리는지"입니다.

> 실무 조언: `i++ + ++i` 같은 코드는 **절대 쓰지 마세요.** 시험 문제일 뿐입니다.
> 한 문장에서 같은 변수를 두 번 바꾸면 읽는 사람이 반드시 틀립니다.

## 문제 2 — 산술변환

```
30                    ← a + b        byte+byte 인데 결과는 int
30                    ← (byte)(a+b)  캐스팅해서 byte에 담음
98                    ← x + 1        'a'(97) + 1
3                     ← 10 / 3       int 나눗셈, 버림
1                     ← 10 % 3
-1                    ← -10 % 3      부호는 왼쪽 피연산자를 따라간다
3.3333333333333335    ← 10.0 / 3
```

### `byte c = a + b;` 는 왜 에러인가

```
error: incompatible types: possible lossy conversion from int to byte
```

**산술변환 규칙:** `int` 보다 작은 타입(`byte`, `short`, `char`)은 연산할 때
**무조건 `int` 로 올라갑니다.** `byte + byte` 조차 결과가 `int` 입니다.

이유는 CPU가 4바이트 단위로 계산하는 게 효율적이기 때문입니다. 그리고 이 규칙이
없으면 `byte 100 + byte 100` = 200 이 byte 범위를 넘어 조용히 망가집니다.

고치려면 `byte c = (byte) (a + b);` — 괄호 위치를 주의하세요.
`(byte) a + b` 로 쓰면 `a` 만 캐스팅되고 결과는 여전히 `int` 입니다.

### `-10 % 3` 이 -1 인 이유
나머지의 부호는 **나누어지는 쪽(왼쪽)** 을 따릅니다. `-10 = 3 × (-3) + (-1)`.
그래서 `n % 2 == 1` 로 홀수를 판별하면 **음수에서 틀립니다.** (`-7 % 2` 는 `-1`)
안전한 건 `n % 2 != 0` 입니다.

## 문제 3 — 단축평가

```
0        ← false && (++k > 0) 이후. k가 안 변했다
0        ← true  || (++k > 0) 이후. 여전히 안 변했다
1        ← true  && (++k > 0) 이후. 이때만 변했다
false true true
```

```
false && ???   →  왼쪽이 false면 오른쪽이 뭐든 결과는 false. 오른쪽을 아예 안 읽는다
true  || ???   →  왼쪽이 true면 오른쪽이 뭐든 결과는 true.  오른쪽을 아예 안 읽는다
```

이걸 **단축평가(short-circuit)** 라고 합니다. 최적화처럼 보이지만 실제 용도는 **안전장치**입니다.

```java
if (str != null && str.length() > 0)     // 순서가 생명
```
`str` 이 `null` 이면 왼쪽이 `false` 라서 `str.length()` 를 아예 실행하지 않습니다.
순서를 뒤집으면 `null` 일 때 프로그램이 죽습니다. 이 패턴을 앞으로 수천 번 씁니다.

> `&` `|` (하나만 쓰기) 는 단축평가를 **하지 않고** 양쪽을 무조건 계산합니다.
> 논리 판단에는 항상 `&&` `||` 를 쓰세요.

## 문제 4 — 삼항 연산자

```
B        ← score(85) >= 90 ? "A" : score >= 80 ? "B" : "C"
5        ← p > q ? p : q
크다      ← p > q ? "크다" : 0
```

첫 줄의 중첩은 오른쪽부터 묶입니다. 즉 이렇게 읽습니다:
```java
score >= 90 ? "A" : (score >= 80 ? "B" : "C")
```

**세 번째 줄은 놀랍게도 컴파일이 됩니다.** `String` 과 `int` 를 섞었는데도요.
자바가 `0` 을 `Integer` 로 감싸고, 두 타입의 공통 조상인 `Object` 를 결과 타입으로
잡기 때문입니다. `println(Object)` 가 호출되어 "크다"가 찍힙니다.

컴파일이 된다고 좋은 코드는 아닙니다. 결과 타입이 `Object` 라서 `String` 변수에는
못 담습니다.
```
String s = p > q ? "크다" : 0;
error: incompatible types: bad type in conditional expression
    int cannot be converted to String
```
**삼항 연산자의 두 결과는 같은 타입으로 맞추세요.**

## 문제 5 — 대입 연산자

```
13   ← i += 3    (10 + 3)
8    ← i -= 5    (13 - 5)
16   ← i *= 2    (8 * 2)
5    ← i /= 3    (16 / 3 = 5, 버림)
1    ← i %= 4    (5 % 4)
```

`i += 3` 은 `i = i + 3` 과 같습니다. 그런데 한 가지 숨은 차이가 있습니다:
**복합 대입 연산자는 캐스팅을 자동으로 해줍니다.**

```java
byte b = 10;
b = b + 1;    // 에러! int를 byte에 넣으려 한다
b += 1;       // OK   — 내부적으로 (byte)(b + 1) 로 처리된다
```

문제 2에서 본 `byte c = a + b` 에러와 이어지는 이야기입니다.

## 문제 6 — `==` 함정

```
true     ← 1 == 1.0       int가 double로 올라가서 비교. 값이 같다
true     ← 'A' == 65      char도 속은 정수
true     ← s1 == s2       둘 다 "hi" 리터럴 → 같은 객체를 가리킨다
false    ← s1 == s3       new String() → 새 객체. 주소가 다르다
true     ← s1.equals(s3)  내용을 비교하니 같다
```

지금 단계에서 가져갈 건 딱 하나: **문자열 비교는 `equals`.**

왜인지는 step05(참조형)에서 풀립니다. 미리 한 문장으로 말하면,
`==` 는 **"같은 상자냐"** 를 묻고 `equals` 는 **"상자 속 내용이 같냐"** 를 묻습니다.
`"hi"` 라고 직접 쓴 리터럴은 자바가 재사용해서 같은 상자를 주지만(그래서 `true`),
`new String("hi")` 는 **일부러 새 상자를 만드는** 명령이라 주소가 달라집니다.

`s1 == s2` 가 `true` 인 게 오히려 함정입니다. 이것 때문에 "`==` 도 되네?" 하고
쓰다가, 값이 사용자 입력이나 DB에서 오면 갑자기 `false` 가 되어 버그가 납니다.
**예외 없이 `equals`** 를 쓰세요.

## 문제 7 — 컴파일 에러 vs 실행 에러

**컴파일 에러 (2개)**
```
error: incompatible types: int cannot be converted to boolean
        if (a = 3) { }
              ^
error: incompatible types: int cannot be converted to boolean
        boolean b = 1;
                    ^
```
- `if (a = 3)` — `==` 가 아니라 `=` 를 썼습니다. `a = 3` 의 결과는 `int` 3이고,
  `if` 는 `boolean` 을 요구합니다. **자바는 0/1을 참/거짓으로 취급하지 않습니다.**
  C 언어를 아시면 여기서 헷갈립니다. 자바는 이 실수를 컴파일러가 막아주는 쪽을 택했습니다.
- `boolean b = 1;` — 같은 이유.

**실행 에러 (2개)** — 컴파일은 통과하고, 돌리면 죽습니다.
```
Exception in thread "main" java.lang.ArithmeticException: / by zero
```
- `int c = 10 / 0;`
- `double d = 10 / 0;` ← **이것도 죽습니다.** 여기가 함정입니다.
  `d` 가 `double` 이어도 오른쪽 `10 / 0` 은 **`int` 끼리의 나눗셈**입니다.
  타입은 대입받는 쪽이 아니라 **피연산자**가 정합니다.

반면 실수 나눗셈은 죽지 않고 특수값을 냅니다:
```java
System.out.println(10.0 / 0);   // Infinity
System.out.println(0.0 / 0);    // NaN  (Not a Number)
```
정수 0으로 나누는 건 예외, 실수 0.0으로 나누는 건 `Infinity`. 이 비대칭을 기억하세요.

### 과제 1 — Calculator
```java
System.out.println(n1 + " + " + n2 + " = " + (n1 + n2));
```
마지막 `(n1 + n2)` 의 **괄호가 필수**입니다. 괄호를 빼면 `+` 가 왼쪽부터 계산되면서
앞의 문자열에 이어붙어 `17 + 5 = 175` 가 됩니다. 한 번 빼고 돌려보세요. 잊지 못합니다.

정확한 값: `(double) n1 / n2` → `3.4`

### 과제 2 — EvenOdd
```java
System.out.println(n + "은 " + (n % 2 == 0 ? "짝수" : "홀수"));
```
여기도 삼항 연산자 전체를 괄호로 싸야 합니다. `+` 가 `==` 보다, `==` 가 `?:` 보다
우선순위가 높아서, 괄호를 빼면 `(n + "은 " + n % 2) == 0` 으로 묶여 컴파일 에러가 납니다.

```
error: bad operand types for binary operator '=='
  first type:  String
  second type: int
```

**"연산자 우선순위를 모르면 괄호를 쳐라"** 가 실무 규칙입니다. 괄호는 공짜입니다.

### 과제 3 — Max3
```java
int maxAB = v1 > v2 ? v1 : v2;        // 먼저 둘 중 큰 걸 고르고
int max   = maxAB > v3 ? maxAB : v3;  // 그걸 세 번째와 비교
```
한 줄로 쓰면 `(v1>v2?v1:v2) > v3 ? (v1>v2?v1:v2) : v3` 인데, 같은 식을 두 번 쓰게 되고
읽을 수 없습니다. **변수로 쪼개는 게 정답입니다.** 짧은 코드가 좋은 코드가 아닙니다.

### 과제 4 — DigitSum
| 자리 | 식 | 계산 | 값 |
|---|---|---|---|
| 천 | `num / 1000` | 4827 / 1000 | 4 |
| 백 | `num / 100 % 10` | 48 % 10 | 8 |
| 십 | `num / 10 % 10` | 482 % 10 | 2 |
| 일 | `num % 10` | 4827 % 10 | 7 |

**패턴:** `/` 로 **뒤를 잘라내고**, `% 10` 으로 **맨 뒤 한 자리만 남깁니다.**
이 두 동작의 조합으로 어느 자리든 뽑을 수 있습니다. 반복문을 배우면(step03)
`while (num > 0) { sum += num % 10; num /= 10; }` 로 자리수에 상관없이 처리할 수 있습니다.

### 과제 5 — LeapYear
```java
boolean isLeap = (year % 4 == 0 && year % 100 != 0) || (year % 400 == 0);
```
```
2024년은 윤년        4의 배수 O, 100의 배수 X          → 앞 괄호 true
1900년은 윤년 아님    4의 배수 O, 100의 배수 O(제외)     → 둘 다 false
2000년은 윤년        100의 배수지만 400의 배수 → 뒤 괄호 true
```
한국어를 그대로 옮기는 게 요령입니다:
**"(4의 배수**이고 **100의 배수가 아니다)** 또는 **(400의 배수다)"**
→ `(A && !B) || C`. 조건이 복잡할 때는 코드보다 **문장을 먼저** 쓰세요.

### 과제 6 — ShortCircuit
```
false && ... 이후 count = 0  (오른쪽을 아예 안 봤다)
true  && ... 이후 count = 1  (오른쪽을 봤다)
true  || ... 이후 count = 1  (오른쪽을 안 봤다)
```
`count` 가 안 늘어난 것이 "실행되지 않았다"는 **증거**입니다.
이렇게 부수효과(side effect)로 실행 여부를 확인하는 건 디버깅의 기본 기술입니다.
