## 문제 1 — 나눗셈과 형변환

```
3        ← a / b        (int / int = int. 0.5는 버려진다. 반올림 아님!)
1        ← a % b        (7을 2로 나눈 나머지)
3.5      ← (double) a / b
3.5      ← a / (double) b
3.0      ← (double) (a / b)
```

**핵심:** `/` 의 결과 타입은 **피연산자 타입**이 정합니다.
- `int / int` → `int` (소수점 **버림**)
- 한쪽이라도 `double` → `double`

마지막 두 줄이 다른 이유는 **괄호 위치 = 캐스팅 타이밍**입니다.

```
a / (double) b   →  7 / 2.0     →  3.5    나누기 전에 double로 바꿨다
(double)(a / b)  →  (double) 3  →  3.0    이미 3이 된 뒤에 바꿨다 (0.5는 이미 사라짐)
```

이미 버려진 정보는 나중에 캐스팅해도 돌아오지 않습니다. **순서가 결과를 바꿉니다.**

## 문제 2 — char 와 정수

```
65       ← int i = ch;         'A' 의 유니코드 값. char → int 는 자동 형변환
66       ← ch + 1              char 가 int 로 올라가서 계산됨 (산술변환)
B        ← (char)(ch + 1)      66을 다시 문자로 되돌림
A1       ← "" + ch + 1         왼쪽부터: ""+'A' → "A", 그다음 "A"+1 → "A1"
```

- `char` 는 **속이 정수**입니다. 문자 모양으로 보이지만 안에는 유니코드 번호가 들어 있습니다.
- `char + int` 는 결과가 `int` 입니다. 문자로 보고 싶으면 `(char)` 로 되돌려야 합니다.
- 마지막 줄이 `A1` 인 이유: `+` 는 **왼쪽부터** 계산되고, 한쪽이 문자열이면 문자열 이어붙이기가
  됩니다. `"" + ch` 에서 이미 문자열이 되었으니 `1` 도 문자로 붙습니다.
  (`"" + (ch + 1)` 로 괄호를 치면 `66` 이 됩니다. 직접 확인해보세요.)

## 문제 3 — 오버플로

```
-128
```

`byte` 의 범위는 **-128 ~ 127** 입니다. 최대값 127에서 1을 더하면 넘칠 곳이 없어서
**최소값으로 한 바퀴 돌아갑니다.** 자동차 주행거리계가 999999에서 000000으로 돌아가는 것과 같습니다.

```
... 125  126  127  -128  -127  -126 ...
                ↑ 여기서 뚝
```

중요한 건 **에러가 안 난다**는 점입니다. 조용히 틀린 값이 됩니다. `int` 도 마찬가지로
21억을 넘으면 음수가 됩니다. 그래서 큰 수를 다룰 땐 `long` 을 씁니다.

## 문제 4 — 실수의 정밀도

```
0.30000000000000004
false
0.10000000149011612
```

`0.1` 을 2진수로 바꾸면 **0.0001100110011...** 로 무한히 반복됩니다. 10진수 1/3을
0.3333... 으로 끝없이 써야 하는 것과 같습니다. 그런데 저장 공간은 유한하니 **어딘가에서
잘라야** 합니다. 그 잘린 오차가 계산에서 드러난 것입니다.

- 마지막 줄: `float` 은 32비트라 오차가 더 큽니다. `double`(64비트)에 옮겨 담으면
  그 오차가 그대로 보입니다. `float` 이 0.1이라고 믿고 있던 값은 실제로
  `0.10000000149011612` 였던 겁니다.

**실무 규칙 두 개만 기억하세요.**
1. 실수는 `==` 로 비교하지 않습니다. (차이의 절댓값이 아주 작은지를 봅니다)
2. **돈 계산에 `double` 을 쓰지 않습니다.** `BigDecimal` 을 씁니다. (나중에 배웁니다)

## 문제 5 — 컴파일 에러 (8줄 중 7줄)

한 번에 다 안 나옵니다. 하나씩 고쳐가며 뽑아낸 실제 메시지입니다.

| 코드 | 에러 메시지 | 이유 / 고치기 |
|---|---|---|
| `int a;`<br>`println(a);` | `variable a might not have been initialized` | 지역변수는 **직접 초기화해야** 쓸 수 있다 → `int a = 0;` |
| `long big = 10000000000;` | `integer number too large` | 리터럴 `10000000000` 은 기본이 `int` 라 범위 초과 → `10000000000L` |
| `float f = 3.14;` | `incompatible types: possible lossy conversion from double to float` | 소수점 리터럴은 기본이 `double` → `3.14f` |
| `char c = "A";` | `incompatible types: String cannot be converted to char` | `"A"` 는 문자열 → `'A'` (작은따옴표) |
| `int x = 3.5;` | `incompatible types: possible lossy conversion from double to int` | 값 손실 → `(int) 3.5` (결과는 3) |
| `MAX = 20;` | `cannot assign a value to final variable MAX` | `final` 은 한 번 정하면 못 바꾼다 |
| `byte small = 200;` | `incompatible types: possible lossy conversion from int to byte` | `byte` 는 127까지 → `(byte) 200` (결과는 -56) |

`final int MAX = 10;` 줄만 정상입니다.

**`possible lossy conversion` 이 이 표에 4번 나옵니다.** 이게 step01에서 가장 자주 만날
에러이고, 뜻은 항상 같습니다: **"큰 그릇에서 작은 그릇으로 옮기려 한다. 흘릴 수 있으니
정말 그럴 거면 `(타입)` 으로 직접 말해라."**

## 문제 6

```java
int i = 10;
double d = i;         // OK  — int(4byte) → double(8byte). 큰 그릇으로 가니 안전
int back = d;         // 에러 — double → int. 소수점을 흘릴 수 있다
int back = (int) d;   // 고침 — "흘려도 괜찮다"고 내가 명시
```

```
error: incompatible types: possible lossy conversion from double to int
```

이게 **자동 형변환 화살표의 방향**입니다.

```
byte → short → int → long → float → double     ← 방향대로면 캐스팅 생략 가능
              char ↗                             ← 거꾸로면 (타입) 필수
```

> `long`(8byte) → `float`(4byte) 이 자동 형변환이라는 게 이상해 보입니다. 크기는 줄지만
> `float` 은 지수 표현이라 **표현 범위**는 더 넓습니다. 정밀도는 잃을 수 있지만
> 값의 크기 자체는 담을 수 있어서 자동 형변환으로 허용합니다.

### 과제 2 — TimeConvert
```java
int hour   = totalSeconds / 3600;         // 2
int minute = totalSeconds % 3600 / 60;    // 2800 / 60 = 46
int second = totalSeconds % 60;           // 40
// → 10000초 = 2시간 46분 40초
```
`minute` 을 구할 때 `% 3600` 을 **먼저** 해서 "시간을 뺀 나머지"를 만드는 게 핵심입니다.
`/` 와 `%` 는 우선순위가 같아서 왼쪽부터 계산되니 `totalSeconds % 3600 / 60` 이 의도대로 됩니다.

### 과제 3 — Swap 추적표
| 실행한 줄 | x | y | temp |
|---|---|---|---|
| 초기 | 10 | 20 | - |
| `temp = x;` | 10 | 20 | **10** |
| `x = y;` | **20** | 20 | 10 |
| `y = temp;` | 20 | **10** | 10 |

`temp` 없이 `x = y; y = x;` 로 하면 둘 다 20이 됩니다. 첫 줄에서 x의 원래 값이
덮어써져 사라지기 때문입니다. **대입은 복사가 아니라 덮어쓰기**입니다.

### 과제 4 — CastLab (여기가 이 단계의 핵심)
```
1) (int) 3.99      = 3        ← 반올림이 아니라 버림!
2) (char) 65       = A
3) (int) '9'       = 57       ← 9가 아니다
4) '9' - '0'       = 9        ← 이게 숫자를 얻는 방법
5) (byte) 300      = 44       ← 오버플로
```

**3번이 왜 57인가:** `char` 안에 들어 있는 건 "문자 9"의 유니코드 번호입니다.
`'0'`~`'9'` 는 48~57번에 나란히 배치되어 있어서 `'9'` 는 57입니다.

**4번이 왜 되는가:** 나란히 있으니 **시작점 `'0'`(48)을 빼면** 순서 번호가 나옵니다.
`57 - 48 = 9`. 이건 앞으로 문자열을 숫자로 바꿀 때 계속 쓰는 관용구입니다.

```
문자:  '0'  '1'  '2' ... '8'  '9'
번호:   48   49   50      56   57
        └── 각각 48을 빼면 0~9 ──┘
```

**5번이 왜 44인가:** 300을 `byte`(-128~127)에 억지로 넣으면 상위 비트가 잘려 나갑니다.
`300 - 256 = 44`. 3번과 5번의 공통 교훈: **캐스팅은 "잘 바꿔줘"가 아니라
"잘리든 말든 그냥 넣어"라는 명령**입니다.

### 과제 5 — CircleArea
```java
final double PI = 3.14159;   // final: 실수로 값을 덮어쓰는 걸 컴파일러가 막아준다
```
`final` 을 쓰는 이유는 "바뀌면 안 되는 값"이라는 의도를 **코드에 남기고 컴파일러에게
검사를 맡기는** 것입니다. 사람 기억보다 컴파일러가 정확합니다.

> 참고: 실제로는 `Math.PI` 를 씁니다. 훨씬 정확합니다.
> `System.out.println(Math.PI);` 를 한번 돌려보세요.
